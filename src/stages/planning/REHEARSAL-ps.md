# Rehearsal: SocialBarrier (`.ps`)

- 바탕 골드: `loading`(실제 창 안에서 줄이 위에서 아래로 차례로 채워짐) + `static-card` 구도(위·좌우 여백, 아래로 잘림). 창·줄·토글·입력란·막대는 모두 키트 부품(`Window` 사이드바형, `Row`, `Toggle`, `Field`, `Collapse`, `Meter`, `Badge`).
- 바꾼 것: 사이드바에 수집 채널 토글 4개, 가운데 글 목록(새 글은 `Collapse`로 위에 끼어들며 아래 줄을 밀어냄), 창 막대의 질문 칸은 지우고 다시 입력하는 방식(`a.type`), 오른쪽은 앞 질문의 답(회색 채움)이 흐려지고 장벽 줄 3개+채움 1개가 위에서부터 자람. 좁은 화면(358×342)은 사이드바 없이 질문 → 블로그·카페 토글 → 글 두 줄 띠 → 장벽 순서의 한 단 구도로 다시 짬.
- 게이트 1280: `rehearsal passed`. 남은 경고는 질문을 지우고 입력할 때 글자 폭이 한 글자씩 바뀌는 `jump`(입력 동작, AgentAnswer와 같은 종류)와 촬영 간격 누락으로 인한 `inconclusive`(다른 촬영이 동시에 돌던 때).
- 게이트 390: `rehearsal passed`. 남은 경고는 위와 같음.
- 좁은 화면 높이는 요청의 약 400이 아니라 342: 400이면 보이는 창이 세로로 길어져 `framing` 경고가 나서 정사각(326×326)으로 맞춤.
- 확인하지 않은 것: 다크 모드, Safari·실기기, 재생 중 창 크기를 바꿔 넓은↔좁은 구도가 전환되는 경우, 「다시 보기」 버튼 재생, 촬영 간격이 비지 않은 상태의 재촬영, 별도 검토자의 눈(review.md).
